# Процедурная реализация на Python (КТ2)

Программа автоматизирует операции процесса «Формирование сменного производственного
задания по заказам покупателей» на условном хлебозаводе: сводит заявки на дату отгрузки,
корректирует план выпуска, рассчитывает потребность в сырье, сверяет её с остатками склада,
распределяет партии по печам и сменам и формирует сменные задания и требование-накладную.

Реализация процедурная: только функции и стандартные структуры данных (`dict`, `list`,
`tuple`, `set`), собственных классов и глобальных изменяемых переменных нет.

## Требования

- Python 3.14 (проверено на 3.14.6).
- Внешние библиотеки не используются, поэтому файла `requirements.txt` нет.

## Запуск

Из каталога `src`:

```
python main.py
```

В Windows, если команда `python` не найдена, можно запустить так: `py main.py`.

Параметры командной строки (все необязательные):

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `--data КАТАЛОГ` | каталог с исходными CSV-файлами | `data` рядом с `main.py` |
| `--date ГГГГ-ММ-ДД` | дата отгрузки, на которую формируется задание | ближайшая дата в заявках |
| `--out КАТАЛОГ` | каталог для результатов в CSV | `out` |

## Файлы

| Файл | Назначение |
|---|---|
| `main.py` | разбор параметров и последовательный вызов операций |
| `data_io.py` | чтение CSV, преобразование типов, запись результатов |
| `orders.py` | `consolidate_orders()` - операция «Свести заявки по изделиям» |
| `planning.py` | `build_production_plan()` - операция «Скорректировать план выпуска» |
| `materials.py` | `calc_material_requirements()` (алгоритм 1) - операция «Рассчитать потребность в сырье»; `check_stock()` - операция «Сверить потребность с остатками склада» |
| `scheduling.py` | `schedule_batches()` (алгоритм 2) - операция «Распределить партии по печам и сменам» |
| `documents.py` | `build_shift_tasks()`, `build_requisition()` - операция «Сформировать сменные задания и требование-накладную»; вывод в консоль |
| `data/` | демонстрационные исходные данные |

## Входные данные

Каждый CSV-файл в каталоге `data` соответствует сущности логической модели данных.
Разделитель - точка с запятой, кодировка UTF-8.

| Файл | Сущность |
|---|---|
| `customers.csv` | Покупатель |
| `delivery_points.csv` | Точка доставки (с временем отправления рейса) |
| `orders.csv` | Заявка |
| `order_items.csv` | Позиция заявки (связь заявки и изделия) |
| `products.csv` | Изделие (тип печи, группа, размер партии, время выпечки) |
| `recipes.csv` | Рецептура изделия или полуфабриката (выход на 100 кг муки) |
| `recipe_components.csv` | Компонент рецептуры: сырьё или полуфабрикат, кг на 100 кг муки |
| `materials.csv` | Сырьё |
| `stock.csv` | Остаток сырья (для муки - фактическая влажность) |
| `ovens.csv` | Печь |
| `shifts.csv` | Смена |

Пример входных данных - заявка Z001 (`orders.csv`) и её позиции (`order_items.csv`):

```
order_id;point_id;ship_date;channel;received_at
Z001;D01;2026-11-05;EDI;2026-11-04 09:12

order_id;product_id;quantity
Z001;P01;540
Z001;P02;300
Z001;P03;600
Z001;P05;360
```

В демонстрационных данных намеренно есть повтор заявки (Z009 повторяет Z004),
заявка с ошибкой (Z010 с неизвестным изделием), заявка на другую дату (Z011)
и нехватка маргарина на складе.
